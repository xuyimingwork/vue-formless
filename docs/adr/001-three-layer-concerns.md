# ADR-001：三层关注点隔离（模型 / 布局 / 流程）

- **状态**：Accepted（修订）
- **日期**：2026-08-12
- **修订**：2026-08-17 — 控件表默认跟页走，领域级 `models/*.ts` 单例降为 opt-in；见 [ADR-009](./009-controls-as-protagonist.md)。
- **来源**：动态表单架构设计推演

## 背景

中后台里「新增 / 编辑 / 详情」常挤在同一个表单组件中。字段、校验、布局、接口回填与提交混在一起，导致：

- 只改布局（并排、隐藏、加小标题）却要改整个 `UserForm`
- 模型微调牵动布局，流程却很少变，变更成本不成比例
- 命名与拆分困难（`UserForm` vs `UserFormUI` 等）却说不清职责边界

本质问题不是「叫什么」，而是**一个组件承载了变化频率不同的多种关注点**。

## 决策

按变化频率拆成三层，载体分离：

| 关注点 | 变化频率 | 职责 | 载体 |
|--------|----------|------|------|
| **模型（View-Model）** | 中 | 本页控件表：控件键、默认 component、label、规则等 | 页面 `setup` 或与 SFC 成对的 `*.controls.ts`（领域单见 ADR-009） |
| **布局（Layout）** | 高 | 栅格/分组、显隐、插槽定制、跨域混排 | Vue Template |
| **流程（Flow）** | 低 | 拉详情、回填、联动查询、提交、DTO 适配 | 页面级 `setup` |

业务编排组件（如 `UserForm.vue`）只做组合：声明（或引入）本页控件表、写布局、在 setup 写流程，不把三类逻辑揉进同一套样板标签里。

巨型表单可再拆布局子组件（如 `UserFormBasicInfo.vue`），子组件只接收 Fields / model，纯布局职责。

## 备选方案

1. **单文件大而全 `UserForm.vue`**：实现快，变更局部却牵动整文件，复用差。
2. **仅拆 `UserForm` + `UserFormUI`**：命名暗示「UI 副本」，边界仍模糊，易再次耦合流程与布局。
3. **全量 JSON Schema 引擎**：把三层都塞进配置（见 ADR-002），布局与联动 DSL 膨胀。

## 后果

- **正向**：变更可局部化；模型可跨页面复用（表单、筛选、详情混排）；流程保持薄。
- **代价**：需要约定目录与命名（模型文件 / 编排组件 / 可选布局子组件）；新人需先理解分层，而不是「一个组件写完」。
- **后续**：具体 API 形态见 ADR-003、ADR-004；配置最小单元见 ADR-005。
